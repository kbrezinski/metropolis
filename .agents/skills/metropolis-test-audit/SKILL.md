# Metropolis Test Audit

Follow root [AGENTS.md](../../../AGENTS.md) and audit only the requested scope. The active work is the testbed and its tooling; a test audit does not authorize model development or changes to the running lab. The pytest suite includes offline integration and loopback protocol tests, not just pure functions.

## Choose the right owner

| Change | Coverage belongs here |
|---|---|
| Reusable device behavior in `testbeds/metropolis/devices/` | Test the simulator model: protocol requests/replies, register or assembly semantics, acknowledgements, faults, and communication loss. Another instance of the same model needs no copied tests; add a case only for distinct behavior. |
| GNS3 tooling in `scripts/gns3/` | Test planning, endpoint/port mapping, generated configuration, lifecycle, capture, telemetry, and resource handling with synthetic topology documents and fake external services. |
| Topology library and schemas | Test load/save, validation errors, supported versions, and preserved fields using small custom documents. Preserve package-resource and installed-wheel contracts when affected. |
| Attack tooling in `scripts/attacks/` | Test selected-dataset target resolution, cell profiles, bounded defaults, dry-run dispatch, optional external commands, provenance, and run attribution without executing attacks. |
| Selected dataset configuration | Use `scripts/validate_metropolis_topology.py` for inventory, addresses, links, router scripts, and VLAN consistency. Use the applicable switch-reference, template, build-plan, and firewall checks from AGENTS.md. |

Do not freeze the reference topology's names, IPs, counts, or full inventory in unit tests. Synthetic fixtures may use fixed names and addresses. Keep regression tests of the validator itself: corrupt temporary inputs and assert the intended diagnostic or failure rather than copying the current topology as an expected result.

## Authoring and removal gate

For each new, changed, or proposed redundant test, identify:

1. The observable contract and a credible regression that would break it.
2. Existing coverage and why this case adds protection. Prefer one primary owner; another layer needs a distinct transport, lifecycle, or integration risk.
3. An independently derived expectation, not output copied from the implementation or generated by the subject under test.
4. The correct boundary. Avoid adding production flags, exports, or wrappers solely for testing; use existing external boundaries and dependency injection where appropriate.

A bug regression should fail before the fix for the intended reason and pass afterward; report when baseline proof is unavailable. Before deleting coverage, inspect its owner, callers, and relevant history, and identify the retained protection. Do not delete tests just because they are slow, static, or numerous, or to hide a production failure. Consolidate repeated setup or parameter cases without erasing distinct failure paths.

## Testbed-specific boundaries

- **Dynamic topology:** use small fixtures with changed node names, addresses, dataset paths, and added or absent services when those affect the feature. Keep fixtures independent of the shipped dataset unless testing its validator or package resources. Do not require every new node to add a new test file.
- **Protocol fidelity:** exact packet bytes, register offsets, and assembly layouts are valid contracts. Prefer these and command/status behavior over source greps or internal call shapes. Physical process accuracy and agreement between synthetic measurements are not requirements. Use bounded waits and tolerances for timing; loopback tests do not prove live cyclic rates.
- **Capture:** distinguish declared link IDs from GNS3 IDs; include endpoint adapter/port identities. Preserve builder-to-capture mapping, uncabled-link reporting, actual packet-file validation, hashes, partial starts, and cleanup after API errors or Ctrl-C. Stop only captures known to have started; a missing file path is a failure. Fake API success alone does not prove a PCAP was saved.
- **Telemetry:** protect incremental output, UTC collector timestamps, run/source/stream attribution, raw malformed lines, and missing-source reporting. Keep timeline actions, network syslog research telemetry, and Docker simulator diagnostics distinct.
- **Compute and resources:** mock GNS3, Docker, SSH, and SDK/network boundaries, including remote compute identities. Keep read-only measurement/drift checks, explicit persistent baseline setup, and temporary profile enforcement/restoration as separate contracts. Preserve partial-write, interruption, and recovery coverage when those paths change.
- **Mocks:** supply external responses, not the behavior being asserted. Assert external commands or request fields when they define the integration contract; avoid pinning private call order unless ordering protects startup, persistence, or cleanup. Use small packet/file fixtures for output validation.
- **Isolation:** local wire tests use loopback and ephemeral ports, with bounded workers and cleanup. Default tests must not contact live GNS3/computes or launch external malware, and must not depend on the user's `METROPOLIS_LAB_ACK` setting. The user verifies actual lab cabling, isolation, routing, enforcement, and traffic.

## Validate and report

- Reuse existing file-based imports for scripts and devices; do not package them solely for tests. Preserve shared setup in [tests/conftest.py](../../../tests/conftest.py), including environment configuration before torch imports, without adding model-related work to a testbed task.
- Use Python 3.12, uv, and the settings in [pyproject.toml](../../../pyproject.toml). Keep pytest caches, temporary files, and compiler caches under ignored `.venv/`; any separate `--basetemp` must also stay there.
- Run focused owner tests, then affected siblings and applicable offline validators for the changed behavior. Inspect skipped build-plan links; a zero exit code does not establish complete cabling. Run Ruff when Python changes. Do not invoke live GNS3 for an offline test task.
- Report protected contracts, consolidation/removals, checks actually run, and remaining limitations. Distinguish mocked, loopback, and live evidence; do not claim unmeasured savings or live verification.
