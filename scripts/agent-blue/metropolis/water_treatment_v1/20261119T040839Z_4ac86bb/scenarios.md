# Curated Metropolis cyber kill chains

Reviewed 2026-11-19 04:08 UTC at Git `4ac86bb` (dirty working tree).
Dataset: `testbeds/metropolis/datasets/water_treatment_v1`. Catalog: `scripts/attacks/scenarios/v1.json`. This focused review selects five plausible internal OT-effect chains; it does not treat catalog count as a target.

## What is and is not established

The address plan separates plant process VLANs, SCADA/engineering/MQTT services, HMI VLANs, a DMZ, enterprise, attack lab, and two remote process LANs. Six routers and eight actual switch appliances are declared; named plant/operations access segments are logical labels. Physical links are planned, while remote operational routing uses logical IPsec VTIs over a shared WAN underlay. `testbeds/metropolis/datasets/water_treatment_v1/topology/address-plan.yaml:7-208`; `testbeds/metropolis/datasets/water_treatment_v1/device_instances/infrastructure.yaml:16-245`; `testbeds/metropolis/datasets/water_treatment_v1/topology/links.yaml:5-14,19-323`.

The firewall renderer makes the baseline more specific than the YAML alone: it generates zone and ruleset default-drop actions, accepts established/related traffic, and inserts new-flow accepts for the selected source CIDR, destination CIDR, transport and port. It rejects baseline attack-lab flows. Thus an unmatched routed flow is **blocked by the generated baseline, if that configuration was applied**. Same-VLAN movement does not cross that firewall. Router configuration is an explicit build step; no live readback was performed. `testbeds/metropolis/datasets/water_treatment_v1/topology/firewall-policy.yaml:1-47`; `scripts/gns3/firewall_policy.py:701-720,776-824`; `scripts/gns3/build_topology.py:101-110,186-200`.

**Correction to the earlier review:** it called engineering→dosing TCP/502 and attack-lab→OT traffic “unknown” because the YAML lacks a default-action field. The generated default-drop rules make those paths blocked under the intended baseline. The earlier report remains an immutable prior run; this report supersedes that conclusion.

An external adversary has no declared entry path to any foothold below. Each timeline has two entry variants: **internal** means the named node is already compromised (an assumption); **external** adds a `T-1` hop from outside the declared topology to that node, marked unknown. The rest of the timeline is identical. `T1` onward indicates event order, never measured elapsed time. “Permitted” refers to the intended network path, not to authentication, command acceptance, or live enforcement.
